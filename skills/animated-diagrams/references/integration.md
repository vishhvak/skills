# Integrate a scene with another host

Keep the scene module's `meta` and `mount()` exports. Import it, call `mount(host, context)` once, pass time in seconds to `render(t, {playing})`, call `reset()` for Replay, and `destroy()` before navigation or unmount. Supply the five clock/context functions `pause`, `play`, `seek`, `getTime`, and `announce`, plus `sound(eventName)` and `prepareSound()` for the scene's semantic effects. Read [audio.md](audio.md) when the reference may carry sound and configure one `createSceneSound` instance beside the scene; its deterministic voices are synthesized from measured source evidence, never from an original track or sliced sample. Give the host a real width and height; the gallery's CSS is not automatically present in another app.

Preserve the owning app's clock and controls. A scene's user interaction must pause that clock and retain manual overrides until the app invokes Replay. Import its direct dependencies and preserve local fonts and licenses. Keep interactive state in the scene instance rather than putting it in global variables shared by mounts.

## Narrated tutorials

When building or extending a narrated lesson, locate the installed `narrated-tutorials` skill (the [sibling copy](../../narrated-tutorials/SKILL.md) is available in this repository). Read its `SKILL.md`, then `references/player-data.md` and `references/verification.md`. It owns voice generation/cloning, alignment, the guiding cursor and continuous playback, including a configurable upstream Breeze TTS API for voice design or user-supplied reference cloning, plus an optional VoxCPM path. Its voice workflow requires no particular host or named speaker preset. If unavailable, keep the standalone diagram usable and report the missing narration capability; it is optional for unnarrated diagrams. For the richer composition and motion of these studies, use the narrated compiler's `diagram` field; read that skill's `references/diagram-modules.md`. Basic `scenes` are an intentional schematic mode, not a substitute for these authored visuals.

The narrated compiler accepts a section `diagram` with a local `directory`, an `entry` module, and named word-aligned `cues`. It packages the files and mounts the module through `diagram-host.js`, forwarding the narration clock. Author the scene against those cue times; no generated-router patch is needed. Keep the scene's dependencies inside its directory and choose only one visual mode per section.

For another host that needs the older `demoEngine` paint interface, use the tested [diagram adapter](../assets/diagram-adapter.mjs). The narrated compiler itself uses its built-in diagram host. Copy it beside the generated scene and import `createDiagramAdapter`. It accepts `(scene, controls, toSceneTime)` and implements the player's `paint(audioTime, {playing, seeking, ...})` options-object contract. Both values are needed: a paused non-seek paint stays silent, as does an active seek. Passing that options object as a boolean would disable every scene effect.

Wire `controls` to the player's actual pause/play/seek and announcement functions and to the configured `sound(eventName)` and `prepareSound()` callbacks. Map important transitions to narration cues with `toSceneTime`; the adapter clamps finite mapped seconds to the scene duration. Call its `stop()` when the host pauses manual motion, `reset()` for Replay, and `destroy()` on unmount. A manual handler prepares audio in the gesture before scheduling work; if preparation is awaited, apply the visual action and effect together only while its generation is current and the scene is mounted.

Import modules before choosing an adapter, or guard asynchronous imports against navigation so a stale load cannot replace the active section. Keep semantic events at their visual transition boundary. The adapter's focused test is `node {baseDir}/tests/adapter.mjs`.

The current player loads `app.js` as a classic script. Dynamic `import()` works there; static `import` requires intentionally converting the script and checking its other bindings. Copy custom scenes and the shared `sound-events.js`, `sfx-voices.js`, and `sound.js` modules under the generated site's static assets and update the generated site's routing, not the installed skill files during an ordinary lesson build.

Verify active effect playback after a gesture, pause cancellation, speed changes, backward word seeks, Replay, manual actions, and section changes with the adapted scene. Verify that passive seeks remain silent, transport controls do not beep, silent references stay silent, and no original comparison audio is routed into the replica; keep the reference video muted. A lesson without audible reference sound does not invent SFX, while narration remains independent and continuous. Editing must pause the owning clock; selection and manual overrides must survive seek until Replay. Keep the tutorial's continuous-play checks, including real section and chapter advancement. An adapter that renders a still frame, replays effects from a seek, or puts a scene effect on a separate clock has not passed narration synchronization QA. Structural checks do not certify perceptual sound parity; record browser listening evidence separately.

Check the scene at the host's real rendered size and use the host font registration. Standalone gallery proportions can turn readable source labels into tiny or overlapping text in a split narrated player. Adjust the composition/type scale there before declaring the integration complete.
